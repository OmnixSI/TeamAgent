# 架构

[← 回到 README](../README.md)

## 组成

| 部件 | 是什么 | 在哪 |
|---|---|---|
| Worker | 入口。收 HTTP 请求和每 2 分钟一次的定时触发，转给 Hub | `src/index.ts` |
| Hub | 唯一的常驻 Durable Object。握着 QQ 长连接，跑每一轮对话、定时任务、后台任务，带一个 SQLite 数据库 | `src/hub.ts` |
| Computer | 第二个 Durable Object，背后是一台容器（云电脑）。按需开机，用完就关 | `src/computer.ts` |
| 绑定 | `HUB`、`COMPUTER`、`FILES`（R2）、`BROWSER`（无头浏览器）、`AI`（Workers AI）、`VERSION` | `wrangler.toml` |

Hub 因为握着长连接而 24 小时在线，这一项固定占掉套餐里 Durable Object 在线时长的八成多，所以不能再有第二个常驻对象。Computer 不常驻。

QQ 的 Webhook 用不了（腾讯访问不到 `*.workers.dev`），所以用长连接。`/qq/events` 已经写好，有了自己的域名就能切过去，Hub 就不必常驻。

## 一轮对话怎么走

1. QQ 把群消息推到 Hub 持有的长连接（`src/gateway.ts`），消息落库；图片和文件同时另存一份，因为 QQ 的链接会过期。
2. 被 @ 或被叫到几乎不等，普通闲聊等 2.2 秒，把连发的几句合起来看。
3. 同一个模型看到真实的聊天记录和图片，自己决定：不说话（`PASS`）、直接回、或调工具后再回（`src/core.ts`）。没有单独的“判定模型”。
4. 推理强度分三档：没人叫它时不思考地看一眼，约 1 秒决定接不接；开口回话用 high；调了查资料、跑代码这类干活的工具后用 max。
5. 回复按 QQ 的习惯发：闲聊拆成一两条短句，认真回答发成一条。

图有没有发出去、定时有没有建好，模型只能从工具返回值知道，所以不会出现“画好了”但没图。

提示词怎么拼、为什么这样排，见 [模型、提示词和记忆](model-and-memory.md)。

## 后台任务

定时任务、先立计划的多步任务（`plan`）、做书（`make_book`）、Bot 自己做名下的任务，都是后台任务（`job` 表）：

- 不占着群聊，期间照常聊天；`jobs` 工具能查进度、能叫停。
- 每做完一步把进度存到 R2。进程重启后，下一次时钟会把没做完的任务从上一步接着做（最多接两次）；做书已经画好的页不重画。接不上会在群里说没做完。
- 定时任务失败会在群里说。没人说话时 QQ 可能不收主动发的图和文件，这时成品排队，下一个人说话时补发。

## 时钟

Hub 每 20 秒醒一次：检查长连接、跑到点的定时任务，并调用每个功能模块的 `tick`。按固定时间做的事：

| 时间 | 做什么 |
|---|---|
| 北京 00:00 | 账目日报 |
| 北京 02:30 | 从前一天的聊天里补记任务 |
| 北京 02:40 | 团队仓库体检（装依赖、跑测试） |
| 北京 03:10 | 数据备份到 R2 |
| 悉尼 04:30 | 把当天聊天整理进长期记忆 |
| 北京 10:30 | 每日自检 |
| 周日北京 21:30 | 团队战报和本周之星颁奖 |
| 每半小时 | 读组织仓库的活动；把攒着的任务动静合成一条发群里 |

## 部署和重启

- 部署不会自动替换 Hub，因为它握着长连接。Worker 的定时触发发现版本号不一致会让 Hub 自己重启；想立刻生效用 `POST /admin/restart`。
- 重启时等正在回话的那一轮结束；后台任务最多等十分钟，超过就重启，由接续机制接手。
- 重启后 QQ 会话自动续上，期间没回的 @ 消息会补回。
- Computer 不一样：机器开着的时候一直用旧代码，要等空闲关机一次（约 90 秒没人用）才换上。

## 功能模块怎么挂进来

每个模块一个文件，在 `src/feat/`，通过 `src/feat/types.ts` 的接口提供这些东西中的任意几样，在 `src/feat/index.ts` 登记一次：

| 接口 | 作用 |
|---|---|
| `tools(ctx)` | 给模型用的工具 |
| `tick(hub, now)` | 每 20 秒被叫一次，自己判断到没到点 |
| `admin(hub, req, url, body)` | `/admin/…` 下的管理接口 |
| `open(hub, req, url)` | 不带管理令牌的公开路由，只限 `/p/` 和 `/x/` |
| `schema` | 自己的表 |
| `tunables` | 群里可以让 Bot 调的参数（有上下限） |
| `about` | 它对这项能力的自述，问“你怎么实现的”时照这个答 |

加新能力优先照这个做，不动共享文件。
