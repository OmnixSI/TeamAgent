# 模型、提示词和记忆

## 用哪些模型

| 模型 | 用在哪 |
|---|---|
| DeepSeek `deepseek-flash` | 全部对话和推理；也用它的联网搜索、读网页、识图、读文档、语音合成 |
| OpenAI 图像模型（`wrangler.toml` 的 `IMAGE_MODEL`） | 生图、改图 |
| OpenAI 转写 | Workers AI 的免费额度用完之后的长音频转写 |
| OpenAI Python 沙箱 | `run_python` |
| Workers AI | 免费额度内的转写（Whisper）和按意思搜索用的向量 |

推理强度由 `src/core.ts` 按情况选：

| 情况 | 档位 |
|---|---|
| 没人叫它，先看一眼要不要接话 | 不思考，约 1 秒 |
| 开口回话 | high |
| 调了干活的工具（查资料、跑代码、多步任务）、定时任务、后台任务 | max |

## 提示词的顺序

每轮提示词按“越不常变的越靠前”排：

```
人设 → 后来加的规矩 → 长期记忆 → 工具说明 → 当天聊天 → 当天记下的事 → 现在几点、要不要回
```

这样排是因为 DeepSeek 按提示词开头相同的部分给缓存价，命中比不命中便宜 50 倍。白天会变的东西只能放在最后，否则它后面的几万 token 每次都按原价重读。

规矩：往系统提示词或工具说明里加任何白天会变的内容（时间、计数、列表、状态），都会打断缓存。这类内容放到 `buildMessages` 的末尾。改完用 `GET /admin/prompt` 看 `toolsHash` 稳不稳、`cached_share` 掉没掉。

### 2026-11-15 量过的数

真群，一轮约 7 万 token：

| 部分 | 占比（按字数） |
|---|---|
| 当天聊天 | 46% |
| 工具说明 | 43% |
| 人设 | 5% |
| 长期记忆（6,640 字） | 5% |

- 一天里九成的输入命中缓存。
- 当天记下的事原先接在长期记忆后面，每 `remember` 一次，后面的工具说明和全天聊天就按原价重读一遍。挪到末尾之后，测试房间里 `remember` 之后那一轮的缓存命中率从 23% 回到 99%。
- 没人叫它时的快速判断（不带推理）和正式回话（带推理）在服务商那边各有一套缓存，前面一变两套都要重读一遍。这一点没有动：为它牺牲“没人叫时秒判断”不值得。

## 记忆

| 层 | 是什么 | 怎么进提示词 |
|---|---|---|
| 长期记忆 | 一份文档，上限约 6000 字：群友、项目、梗、大家对它的要求、教训、做得好的、惦记的事。每条带日期 | 每轮都在 |
| 当天记下的事 | 白天有人立规矩或纠正，`remember` 立刻记一条 | 每轮都在，放末尾 |
| 当天聊天 | 昨晚整理之后的全部聊天，再加之前的 150 条 | 每轮都在 |
| 全部聊天记录 | 从不删除 | 用 `search_history`、`get_history` 按词和日期翻，`recall` 按意思找 |
| 资料库、图片 | 群里分享过的文章和文件的正文、发过的图 | 用 `library`、`find_image` 找 |

每晚悉尼 04:30 用 max 推理把当天聊天和当天记下的事并进长期记忆，重写一遍（`src/memory.ts`）：

- 对照它现在实际有的工具，删掉过时的规矩（说它做不到、让它用已经不存在的东西）。
- 结果比原文短一半以上会被当成出错，不采用。
- 最近 14 天每晚的旧版本都留着（`memory:hist:*`）。
- `forget` 能当场从长期记忆里删掉对应的几行。

### 为什么没有把记忆分成三层

曾经有过“核心常驻、项目按需、归档检索”的方案。量过之后没做：

- 长期记忆只占每轮提示词的 5%，拆了最多省半成。
- 按需取有代价：规矩和项目没被关键词触发时它就看不到。
- 归档层本来就有：原始聊天全在，被挤出长期记忆的旧细节用 `recall` 能找回。

等长期记忆真的顶到上限、每晚开始挤掉还有用的内容时再考虑。

## 画图流程

1. 主模型在调 `generate_image` 时写明原话、它对意图的理解、要参考的图、要先上网查长相的对象。
2. 找参考：保存过的形象（原话里点到名字的自动带上），加上网找到的每个具体对象的真实长相。
3. 设计画面（max 推理，能看到全部参考图）：定主体、构图、风格、图中文字、尺寸和质量，写出提示词。
4. 出图。成品连同原话、提示词、用到的参考图一起存（编号 `g12`）。之后说“接着改这张”，会把当初的提示词带上，只改被要求的部分。

图像接口拒绝某一版时，带着它给的原因重新设计一版离原意最近的再画，最多三版。代码在 `src/draw.ts`。

## Bot 能自己改什么

群里让它改自己的毛病时，它用 `self_update`：

| | 内容 |
|---|---|
| 能改（立即生效，可撤销，留记录） | `src/config.ts` 和各模块 `tunables` 里有上下限的参数、三段做法说明（人设补充、画图、跑代码）、别人叫它的名字 |
| 不能改 | 代码。它写成改进提议（`propose_code`），在 `GET /admin/changes` |
| 谁说了算 | 群主（`wrangler.toml` 的 `OWNERS`）和群主授权过的人说了直接生效；其他人的先记成提议。授权和收回只有群主本人能做 |

它对自己的描述在 `src/self.ts` 和各模块的 `about` 里。改了架构、存储或流程，要在同一次提交里把这些文字改对，否则它会照旧的说法回答群友。
