结论：最小修法是给本机 Node fetcher 加匿名设备 Cookie 的获取与复用，保留普通详情接口，评论按端点决定是否 WBI；本机已验证详情、UP 主、简介和 3 条评论成功。不登录不能保证取得 CC 正文，签名不能解除登录要求。[本机证据](./bilibili-anonymous-412-evidence-2026-11-12.json)、[yt-dlp 字幕实现](https://github.com/yt-dlp/yt-dlp/blob/e8de28e23c1ecb4a12b2c3dec188c07e998c412c/yt_dlp/extractor/bilibili.py#L255)
核对时间：2026-11-12 悉尼 04:21–04:23；独立调研，未看另一位结果。实测运行于本机 macOS / Node v26.0.0，只创建匿名会话，没有读取浏览器凭据或输出 Cookie 值。[脱敏记录](./bilibili-anonymous-412-evidence-2026-11-12.json)

依据与诊断：
- 同一 BV1xx411c7mD：默认 Node 无 Cookie → 200/code 0；Chrome 142 UA + Referer 无 Cookie → HTTP 412/code -412；同组请求头加 SPI 取得的 buvid3/buvid4 → 200；此序列两次出现。支持“设备会话缺失/不一致”优先排查，不能由此证明每次 412 都是它。[本机证据](./bilibili-anonymous-412-evidence-2026-11-12.json)、[匿名浏览器 Cookie 修复案例 #14830](https://github.com/yt-dlp/yt-dlp/issues/14830)
- 分开记录 HTTP status、JSON code、Content-Type 和端点：本机评论签名错误是 HTTP 200/code -403，设备会话问题是 HTTP 412/code -412，字幕登录要求却是 HTTP 200/code 0 + need_login_subtitle=true；不可统一归为“签名过期”。[本机证据](./bilibili-anonymous-412-evidence-2026-11-12.json)、[评论存档](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/comment/list.md#L857)
- Node fetch 不会替调用方管理浏览器式 Cookie jar；只访问首页、设置 credentials 或只取 SPI JSON 而不显式回传 Cookie 不够。用 response.headers.getSetCookie() 取各条响应头，SPI 的 JSON 字段也要自行变成 Cookie；无需新依赖。[Undici Cookie 文档](https://github.com/nodejs/undici/blob/main/docs/docs/api/Cookies.md)、[Undici #1640](https://github.com/nodejs/undici/issues/1640)
- 匿名获取：GET https://api.bilibili.com/x/frontend/finger/spi，data.b_3→buvid3、data.b_4→buvid4；本机两者均取得。GET https://www.bilibili.com/ 本机返回 200，Set-Cookie 含 buvid3、b_nut，不保证首页同时发 buvid4。[本机证据](./bilibili-anonymous-412-evidence-2026-11-12.json)、[BUVID 存档](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/misc/buvid3_4.md)
- SPI 成功不等于所有接口都认可设备：bilibili-api 历史实现还会 POST /x/internal/gaia-gateway/ExClimbWuzhi 激活指纹；本次详情和评论不激活也成功。建议先用简单方案，仍失败再通过本机真实匿名浏览器建立会话，勿一开始照抄大段固定指纹。[历史实现 get_buvid/_active_buvid](https://github.com/TZFC/bilibili-api/blob/main/bilibili_api/utils/network.py)、[激活端点配置](https://github.com/TZFC/bilibili-api/blob/main/bilibili_api/data/api/credential.json)
- UA/Referer 会影响判定，但不是单独保证：yt-dlp #13736 于 2025-07-21 合并升级 UA 的修复；#14830 又区分网页 challenge 和 playurl 的 Referer 问题。先固定一套一致的近期浏览器 UA 和站内 Referer，对部署请求逐项比较，不把 playurl 的修法泛化到全部 API。[#13736](https://github.com/yt-dlp/yt-dlp/pull/13736)、[#14830](https://github.com/yt-dlp/yt-dlp/issues/14830)
- 频率/IP/HTTP版本/TLS 指纹：官方未公开本场景的判定规则或安全阈值，本次未做因果验证。诊断上，同会话同端点逐项对照，若真实浏览器和 Node 均失败才增加 IP/服务端限制的权重；仅 Node 失败还须排除 Cookie、头和参数差异，不能直接认定 TLS。建议串行、缓存、遇 412 停止密集重试；具体间隔属于工程取舍。[#14830 的不稳定复现和限流讨论](https://github.com/yt-dlp/yt-dlp/issues/14830)、[当前提取器限流处理](https://github.com/yt-dlp/yt-dlp/blob/e8de28e23c1ecb4a12b2c3dec188c07e998c412c/yt_dlp/extractor/bilibili.py#L735)

- 请求头建议基线：User-Agent（固定且与会话一致）、Referer: https://www.bilibili.com/、Cookie（同一匿名会话）；实测还带 Accept: application/json, text/plain, */*。GET 不需 Content-Type，也无证据必须堆 Sec-*；上述是已成功的组合，不声称数学意义上的最小集合。[本机证据](./bilibili-anonymous-412-evidence-2026-11-12.json)、[BBDown 头处理](https://github.com/nilaoda/BBDown/blob/master/BBDown.Core/Util/HTTPUtil.cs#L37)
- WBI 密钥：GET /x/web-interface/nav，匿名 code=-101 仍包含 data.wbi_img.img_url/sub_url，本机证实；取两个 URL 文件名去扩展名为 img_key/sub_key，无需下载图片，勿让通用 code!=0 判断丢弃此数据。[本机证据](./bilibili-anonymous-412-evidence-2026-11-12.json)、[WBI 存档](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/misc/sign/wbi.md)
- WBI 算法仍有效：img_key+sub_key 按公开 64 项映射重排取前 32 字符；加秒级 wts，移除旧 w_rid，键升序、值去掉 !'()*，encodeURIComponent 序列化，w_rid=MD5(query+mixin_key)，原样发送签名后的参数。Node 用 node:crypto 即可；空格须 %20，别被 URLSearchParams 的 + 改写。[算法与映射表](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/misc/sign/wbi.md)、[独立实现](https://github.com/yt-dlp/yt-dlp/blob/e8de28e23c1ecb4a12b2c3dec188c07e998c412c/yt_dlp/extractor/bilibili.py#L144)
- 密钥做短时缓存和单次刷新重签，不硬编码；文档历史观察“每日更替”，yt-dlp 保守缓存 30 秒，确切有效期未知。仅在明确签名错误时重签，不把 HTTP 412 一概当密钥过期。[WBI 存档](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/misc/sign/wbi.md)、[yt-dlp 缓存与签名](https://github.com/yt-dlp/yt-dlp/blob/e8de28e23c1ecb4a12b2c3dec188c07e998c412c/yt_dlp/extractor/bilibili.py#L49)
