## 要点
1. run_steps { steps }：BotTool，untrusted:false，任何成员；validateSteps → runSteps(purpose:"chat") → 文本（S-11）。开关 `off:run_steps`。
2. run_task { title, instructions, request_quote, source_id? }：写工具。权限全部满足才入队：isAutoSender(sender)；source.meta.direct===true；本轮未污染（ctx.isTainted() 为假）；request_quote 在原话里（quoteIn）。任一不满足 → `{ok:false,error_kind:"denied",say:"本机执行只有管理员能派；你可以让我现在出账本/余额/总结这类即时结果"}`（S-13，jobs 不增）。入队：`id='exec-'+source.id`，kind='media'，payload 加 mode:"exec"、want_files:false、effort:"high"、lane:"quick"，INSERT OR IGNORE；返回 `{ok:true,accepted:true,family:"job",id,say:"已排队 #<id后6位>，开始和结束我都会在群里说"}`。开关 `off:run_task`。
3. worker.ts：media claim 成功且 payload.mode==='exec' → `INSERT OR IGNORE INTO outbox(id='job-start:'||id, …,'开始执行 #xxxxxx：<title>')`（outbox 列照现有 INSERT 写法抄）。cron 段：对 mode='exec' AND status='running' 且开始 >5 分钟、>15 分钟各发一次「还在跑，已 N 分钟」（outbox id `job-progress:<id>:5`/`:15`，INSERT OR IGNORE 去重）；pending >10 分钟 → 一次「执行端不在线，任务还在排队 #xxxxxx」（`job-stale:<id>`）。完成/失败沿用现有路径，不改。
4. 导出投递（S-07 投递部分）：新增导出辅助 `enqueueExportFile(e,{groupId,sourceId,filename,csv})`（放在 src/tools/run.ts 导出，D1 的 records_read export 在 D4/D9 阶段调用）：runner 心跳 10 分钟内在线（rg -n "heartbeat" src/worker.ts 找现有在线判断）→ 入队 `id='export-'+sourceId`，payload `{mode:"file", file:{name,content_b64}, message:sourceId, want_files:true, effort:"high", lane:"quick"}`；离线 → 返回 `{online:false}` 由调用方回退文本表。
5. runner/utility.py：调用模型之前判断 `p.get("mode")=="file"`：把 content_b64 解码写到工作目录 `file.name` 后直接走现有交付路径，**不调模型**；文件名要清洗（只取 basename、禁 `..`、禁绝对路径）；单测 mock 断言“mode=file 不调用模型”和路径穿越被拒。
