## 侧发现（只列，不修）

1. **`sk_` vs `sk-` 夹具 id**：`scripts/review-export.py:180,184` 只在 id 字段把 `sk-` 换成 `sk_`；`test/fixtures/daily-push-real.json` 保留原值。按 `rid`/`body` 匹配不受影响，按 id 跨夹具比对会不一致（当前无生产逻辑依赖）。
2. **L5 muted / expired 缺口**：`src/review-report.ts:76-167` 只处理窗口/开关/上限/禁词，没有 `muted(e, group)` 检查，也不把 10:00 后仍未发的 ready 标 expired（`sendOutbox` 的通用过期只看 outbox 行的 `expires_at`，不改 `review_reports.state`）。后果：08:40 恰好 mute 的群仍会收到晨报；10:00 后进程恢复时 ready 行状态会一直停着（不会补发）。P2。
3. **L2 对 mute/reminder 也加「回那条推送」**：`src/semantic.ts:1560` 对成功的 schedule_create 一律回「记下了，…，不想要了回那条推送说「不用再发了」。」；mute 没有出站推送（`src/schedules.ts:751-752` body=null），这句会误导。P2。
4. **address_as 的 `normMember` 不一致**：`src/learning-confirm.ts:185` 用裸 `String(params.member) !== row.requester` 严格比对；`renderRule` 已走 `normMember`（`src/review/rules.ts:39,61,100`）。手工/回填把 `params.member` 写成 `qq:` 前缀时，renderRule 接受、applyLearning 静默不写也不回执。P2。
5. **场景库入口缺失**：worktree 与 `/Users/yanghongming/Projects/.agent` 下都没有 `.agent/scenarios/`；本版可执行入口实际是 `test/learning-accept.mjs`，没有按场景拆分的 `run.sh`。未擅自新建目录，交主程决定是否补。
