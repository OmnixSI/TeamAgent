## 6. claim 开关为什么是关的、今晚能不能开

**为什么关：三层，不是忘了**
1. `~/.inkboard-team/fr-consume.json` 不存在；`loadConsumeConfig` 对缺失文件的默认值是 `enabled:false`。
2. 没有任何调用方：`com.inkboard.team-fr` 的 ProgramArguments 是 `fr-pull.mjs --json`，没有 `--claim`，也不调用 `fr-consume.mjs`。
3. `fr-consume.mjs` 不在 `origin/main`，只在 `pkg/D-F11c @7fafb92` / `release/D`；`fr-ops` worktree 固定 main，所以装好的拉单环境里根本没有消费端。团队记忆里也写着「消费端未做，禁止加 `--claim`」。

**今晚只写开关：安全，但没有用**
- `feature_request` 0 行，没有可领的单；launchd 也不会调用 `fr-consume`。写 `{"enabled":true}` 只是把一个 no-op 开关打开，不会建 worktree、不会领单、不会发群。
- 这一步可以做，但不能算「推进闭环」。

**今晚把开关接上 `--claim`：现在不安全**
- 第一张单会被领走并置 `developing`（6h 租约）；派工、heartbeat、上线回写都没接，6h 后放回、3 次后 failed，群里收到「没做成」。
- 新 worktree 没 `node_modules`，`fr-consume gate` 会直接失败；gate 也没有真实回放/冒烟。
- 所以：**开关文件可以今晚打开；`--claim` 不要接上生产定时任务，除非先做完下面 5 步彩排。**

**今晚可做的最小安全顺序（不改业务代码）**
1. 把 `pkg/D-F11c` 合入 `origin/main`（或让 fr-ops 固定到含 7fafb92 的分支），让拉单环境里有 `fr-consume.mjs`；同时合入 `pkg/F11c-solo @5aa08e3` 的 MG2 预算修复，否则 gate 必红。
2. 在 `fr-consume` 的 gate 前加 `npm ci`（或复用已有的 node_modules symlink），否则 gate 必失败。
3. 写 `~/.inkboard-team/fr-consume.json {"enabled":true}`，先跑 `fr-consume.mjs`（不加 `--claim`）确认 dry-run 0 单。
4. 在本地/预发造一张 queued+build 的测试单，走通 claim → worktree → gate → `fr-report shipped`（stub outbox）→ 确认 `frr-*` 只入队一次；再删测试单和 worktree。
5. 接 BINI/主程的 15 分钟派工：读 `ready-to-dispatch.md`，把 `pkg/FR-<id>` 交给主程；同时每 ≤2h 调 `fr-report heartbeat`。彩排过了再开真单。
