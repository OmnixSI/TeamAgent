## 1. 这个补丁修什么（都是真实回放/真机暴露的）

1. **X 读取器缺 SDK 时必泄漏 Edge 并卡死**：`launch()` 在 `require('sdk/node_modules/playwright')` 抛错后既不关已启动的 Edge，也不返回；Edge 的 child handle 吊住 Node，适配器 45 秒超时杀进程组，Edge 是 detached 自己的组，活下来锁住 profile。回放第一轮因此 45s timeout + 后续 `busy`，实测清出 12 个遗留 Edge。
   修法：SDK 本地/`~/.inkboard-team/sdk` 双路径回退；launch 失败必 `close()`；`close()` 杀整个 Edge 进程组；超时/信号走 `fastShutdown()` 先 SIGKILL 自己的浏览器组；属主已死的 `SingletonLock` 自动清理；适配器 SIGKILL 宽限 120ms→1500ms 并等子进程退出。实测 2.5s 强制超时后遗留 Edge = 0。
2. **雪球链接线上必失败**：`xueqiu:quote` 在契约里但没有命令，真机回放 `tool_not_ready`。修法：`read_social` 把 `/S/<代码>` 桥到已上线的 `stock_quote`（不重写腾讯解析），映射成统一信封（`content_scope=quote`，来源写“腾讯行情”），错误映射 `not_found/timeout/upstream_unavailable/rate_limited`。
3. **X 资料页 author/source_url 为空**：新响应把 `screen_name`/`name` 放到 `core`，`legacy` 里没有。修法：`legacy || core` 回退；适配器允许并透传 `source_url`，`runJob` 不再丢它。
4. **小红书缺签名只有一句泛化 unsupported**：补 `xsec_token` 专用原因；小红书读取器同样加 SDK 回退、`SingletonLock` 清理、退出前 flush。

## 7. P1 返工：强杀遗留 Edge（2026-11-14 19:55–20:00，工程师）

- **来源**：`notes/f9-deliver.md` 的 P1：2.5 s 强杀 4 次中 1 次遗留 8 个 `browser/x` Edge，清理耗时 4.25 s。
- **根因**：`x-reader.mjs` 用 `detached:true` 启动 Edge，Edge 自成一个进程组；适配器 1.5 s 宽限到期后只 SIGKILL 读取器的组，Edge 组成为孤儿。读取器启动阶段还有一段同步 `require('playwright')`，信号若落在这段里会推迟处理，正好撞上 1.5 s 升级强杀。
- **修法**（`pkg/F9-reader-timeout` @ **0639a3b**，基于 main `a3c9c95`；4 文件 +57/−11，未 push/未部署）：
  1. Edge 不再 `detached`，与读取器同组；`close()` / `fastShutdown()` 只对 Edge 子进程发信号，不再从组内杀组。
  2. CDP 客户端在启动 Edge 之前加载，同步 require 期间不会有活浏览器。
  3. 适配器改为等「整个进程组消失」而不是只等子进程 exit；组还在就 SIGTERM，1.5 s 后一定 SIGKILL；组杀失败回退 `child.kill()`。
  4. 新增 3 个回归：Edge 必须与读取器同组、读取器退出后遗留的浏览器必须被清、成功路径不再白等 1.5 s。
- **验证**：
  - 确定性复现：等 Edge 启动后对读取器组 SIGKILL（比 2.5 s 超时更狠）。旧码 3/3 次各遗留 1 个 Edge；新码 3/3 次遗留 0（200–400 ms 各测 3 轮）。
  - 正常读取（隔离 profile，`HOME=/tmp/f9-home`）：3/3 次遗留 0，耗时 1.4–2.2 s；未触碰真实 `browser/x` Cookie。
  - `npm test`：**2234 例 / 2224 过 / 0 败 / 10 跳过**；`runner/test_fetcher.mjs` 80/80；`npm run check`、`precheck`、`check:ui` 均绿（均在 `a3c9c95` + 本补丁上重跑）。
