# 团队协作

[← 回到 README](../README.md)

这一组是任务清单、Bot 自己干活、积分、看板和本地 AI 接口。代码在 `src/feat/` 的 `tasks.ts`、`teamwork.ts`、`contrib.ts`、`board.ts`、`board-page.ts`、`mcp.ts`、`access.ts`。

## 任务

### 一件任务有什么

| 字段 | 含义 |
|---|---|
| 状态 | 没开始 / 在做 / 做完了 / 不做了 |
| 大小 | 小事 / 普通 / 大活（决定得分） |
| 轻重 | 急 / 普通 / 不急 |
| 先后 | 要等哪几件做完才能开始（`after`）。互相等的排法会被拒绝 |
| 负责人、领取人 | 交给谁；谁（人或他的本地 AI）接了 |
| 截止日期、来由、结果 | 可空；来由是原话里的一小句；结果是交付了什么 |
| 拆分来源 | 从哪件任务拆出来的（`parent`） |
| 经过 | 每一步谁做了什么（`task_note`），看板上是时间线 |
| 交接材料 | 见下 |

### 任务从哪来

- **群里说的**：有人明确说自己要做某件事，或把事交给某人，Bot 自己记；随口的愿望和玩笑不记。
- **每晚补记**：北京 02:30 把前一天的聊天再过一遍，补上漏记的、标出做完和取消的。每件都要对得上群里的原话，一晚最多新记 8 件。
- **看板**：在任务页新建。
- **本地 AI**：通过 MCP 的 `add_task`。

### 该做的顺序

清单、看板、MCP 都按同一个顺序排：正在做的 → 现在能开工的（急的在前，再按截止日期和先后）→ 还在等别的任务的。前面那件做完，等它的任务会被点名“可以开始了”。

### 交接材料

每件任务带着接手的人需要的东西（表 `task_ref`），看板的任务页和 MCP 的 `get_task` 拿到的是同一份。

| 种类 | 内容 | 怎么来 |
|---|---|---|
| 原话 | 提出这件事的人当时在群里说的话，整段照存，带时间和名字 | 记任务时自动抓提问人最近 30 分钟内的最后几条 |
| 报告 | 调研报告、方案、结论的全文（最多 4 万字） | Bot 用 `attach`；本地 AI 用 `attach_material`；看板上粘贴 |
| 链接 | 网页、PR | 同上 |
| 文件 | 文件或图片的编号（`x12`、`g300`） | 同上 |

- 拆出来的子任务自动带上原任务的材料。
- 成文的产出必须有一份文字全文：只挂图片或 PDF，别人的 AI 读不了。Bot 做完自己的任务时没挂会被提醒补上。

## Bot 自己干活

交给 Bot 的任务（负责人是 `bot`）不是记一笔就完了：

1. **自己开工。** 轮到它时自动开始，任务变成“在做”，看板显示“Bot 正在做”。
2. **能做的做完。** 调研就真的去搜去读，写方案就写出来，改代码就让编码代理开草稿 PR。产出挂在任务上。
3. **做不了的拆出去。** 要人拍板的、要线下办的、要别人账号或权限的，它不硬做，从原任务里拆成新任务交给合适的人，写明为什么它做不了、已经做到哪。
4. **该等就等。** 原任务要等拆出去的那件做完才能继续的，会排在它后面，那件做完后自动再轮到它。
5. **收尾。** 做完写上结果。

限制：

| 项 | 值 |
|---|---|
| 时间 | 北京 8:00–23:30 |
| 并发 | 一个群一次只做一件；有别的后台任务在跑就等 |
| 次数 | 一天最多 6 次（`tasks_bot_daily`）；一件任务最多自己试 3 轮，每轮间隔半小时，还没做完就停下来在群里说卡在哪 |
| 开关 | `tasks_bot_auto` |
| 计分 | Bot 自己做完的活不给任何人记分 |

每次开工是一个普通的后台任务，重启后能接着做。

## 群里怎么播报

规则是：群友的事当场说，Bot 自己的事和零碎动静攒起来说。

| 事情 | 怎么说 |
|---|---|
| 群友（或他的本地 AI）接了任务 | 当场一句 |
| 群友做完任务 | 当场表扬，带得分、这周第几件、新拿的称号 |
| Bot 自己开工、做完 | 攒着 |
| 新加任务、拆分、放下、谁可以开始了 | 攒着 |
| 在群里直接跟 Bot 说的 | 不重复提醒，它的回话已经说了 |

攒着的每半小时合成一条（以【任务】开头，最多列 8 条，更多的看看板）。Bot 自己干活时不往群里发长图、PDF 和整篇报告，只说一两句，细节在任务上。

| 参数 | 默认 | 含义 |
|---|---|---|
| `tasks_announce` | `digest` | `digest` 如上；`on` 每件事都当场说；`off` 都不说 |
| `tasks_digest_minutes` | 30 | 攒多少分钟合成一条 |
| `team_praise` | on | 做完任务时的表扬 |
| `tasks_remind` | off | 到期那天早上提醒一句 |

## 积分

### 怎么得分

任务：

| | 分 |
|---|---|
| 小事 / 普通 / 大活 | 5 / 10 / 30 |
| 赶在截止日期前做完 | 再加 5 |
| 当选本周之星 | 20 |

本地 AI 做的算在它主人头上。

组织仓库里的活和接任务（`src/feat/contrib.ts`）。系统每半小时读一次组织的全部仓库，按 GitHub 账号记到人头上，每件事只记一次：

| 事件 | 分 | 每人每天上限 |
|---|---|---|
| PR 合并 | 10 | 无 |
| 开 PR | 2 | 6 |
| 写 issue | 1；写清现象、位置和修法的 2；只有标题的不算 | 8 |
| 审别人的 PR | 2（每个 PR 每人一次） | 6 |
| 合别人的 PR | 1 | 3 |
| 不走 PR 的直接提交 | 0.5 | 3 |
| 接任务 | 1（每件一次，放下了不算） | 3 |

- 这些加起来每人每天最多 20 分，超出的只记账、不算分。
- 随 PR 合进来的提交不重复算；合并提交不算。
- Bot 自己的 `bot/` 分支和机器人账号不算任何人的。
- 账号和人的对应由群主定（`team` 的 `link_github`）。还没对上人的账号，它的活不算进任何人的分，会被列出来等群主认领。
- 每一分都对得上具体的 PR、issue 或提交，`team` 的 `activity` 能逐条看。

### 重新起算

群主说“重新开始统计”，Bot 用 `team` 的 `restart` 办：从那一刻起，之前做完的任务、花掉的分、当过的本周之星奖金、仓库里的活都不再算。任务清单和历届之星还留着，什么都不删。

起算时间、谁多少分一律以工具查到的为准。Bot 不靠记忆和手算报分。

### 称号

| 称号 | 条件 |
|---|---|
| 开张 | 做完第一件事 |
| 五连胜 / 十全 | 累计做完 5 件 / 10 件 |
| 屠龙 | 啃下一个大活 |
| 闪电 | 接手两小时内做完一件 |
| 准点 | 5 件事赶在截止日期前做完 |
| 救火 | 做完一件已经过了截止日期的事 |
| 夜猫子 | 凌晨 0 点到 5 点做完一件 |
| 三天不断 / 一周不断 | 连续 3 天 / 7 天都有做完的事 |
| 驭 AI | 让本地 AI 做完 3 件 |

### 用分换特权

| 特权 | 分 |
|---|---|
| 定制表情包 | 5 |
| 点一段语音 | 10 |
| 甩锅券 | 15 |
| 点一张图 | 20 |
| 专属头衔一周 | 25 |
| 代办券 | 40 |
| 战报封面人物 | 50 |

群主可以加自定的特权。只能花自己的分，不能转让、不能预支。看板的“兑换台账”能看每笔兑换、是否兑现、退分时间；待兑现的由群主结算。

### 每周

周日北京 21:30：

1. 给本周之星发奖状（无头浏览器渲染的一张图）。
2. 用语音宣布获奖者。
3. 颁奖词，点名他做成的具体的事。
4. 战报：这周谁做成了什么、仓库和接活各得多少分、谁手上还压着活。

本周之星得到奖状、20 分奖金、接下来一周的“本周之星”头衔，名字和奖状上功勋墙。开关是 `team_weekly`。

## 看板

`/x/board`。每人用自己的个人链接进：在群里对 Bot 说“给我看板链接”。

| 页 | 内容 |
|---|---|
| 概览 | 这周的进展、自己的分、手上的任务 |
| 任务 | 三栏：没开始（分成“现在就能开始”和“在等别的任务”）、进行中、完成。Bot 在做的那件置顶提示 |
| 任务详情 | 要做什么、原话、材料、要先做完的任务、拆分关系、时间线；能改状态、大小、轻重、先后，能加材料、写进展、交给本地 AI |
| 战绩 | 排行（本周 / 总榜）、每人的仓库和接活得分、称号、最近的动静 |
| 功勋墙 | 本周之星、历届之星和奖状、拿下的大活、各项纪录、称号柜 |
| 兑换 | 余额、特权、兑换台账 |
| 动态、作品和文件、仓库、记忆、监控和额度、工具 | 群聊小结、画过的图和文件、仓库体检、长期记忆、监控和套餐用量、工具箱 |

### 个人链接

- `/x/board/k/<令牌>`：点开后把令牌存进 cookie，再跳到看板。
- 令牌代表这个人在这个群里的身份。服务器只存令牌的哈希。
- 每人最多 5 个有效链接；说“把我的看板链接作废”全部失效。
- 大陆网络打不开 `workers.dev` 时用香港镜像的地址，Bot 给链接时两个都给（见 [网络](network.md#香港镜像)）。

## 本地 AI 接口（MCP）

群友本机的 AI 工具可以直接接群里的活。地址是 `/x/mcp/<令牌>`，令牌就是看板个人链接里那一个；它做的每件事都记成“某某的本地 AI”，分算在这个人头上。

接入，只用运行一次（Bot 给看板链接时会把带令牌的整行给出来）：

```sh
claude mcp add --scope user --transport http teamagent <地址>/x/mcp/<令牌>   # Claude Code
codex mcp add teamagent --url <地址>/x/mcp/<令牌>                              # Codex
```

| 工具 | 作用 |
|---|---|
| `list_tasks` | 按该做的顺序列任务 |
| `get_task` | 一件任务的整份交接材料：要求、原话、报告全文、链接、要等的任务和它们的结果、拆分关系、经过 |
| `claim_task` | 领任务（群里当场说一句） |
| `report_progress` | 记进展（只在看板上，不打扰群里） |
| `attach_material` | 把产出的报告、链接、文件挂到任务上 |
| `complete_task` | 交付（群里当场表扬） |
| `release_task` | 放下，让别人接 |
| `add_task` | 加任务；带 `parent` 就是把自己做不了的部分拆回群里 |
| `search_chat` `get_memory` | 翻聊天记录、看长期记忆 |
| `list_files` `get_file` `repo_status` | 看 Bot 存的文件和仓库体检 |
| `notify_group` | 让 Bot 在群里多说一句（有每日上限） |

通常的流程：`list_tasks` → `get_task` → `claim_task` → 在本地做 → `report_progress` → `attach_material` → `complete_task`。看板任务页的“交给本地 AI”会给出一句可以直接贴给 AI 的话；不想接 MCP 的客户端（比如 DeepSeek）可以点旁边的“复制任务清单”，拿到未完成任务的一行一件 Markdown 清单直接贴过去。

技术上是无状态的 HTTP：只接受 POST，不发会话号；协议版本 2026-07-28，也接受更早的三个版本的握手。每人每天最多调用 500 次（`mcp_calls_daily`）、让 Bot 在群里说 30 句（`mcp_notify_daily`）。
