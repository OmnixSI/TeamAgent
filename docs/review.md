# 2026-11-11 · 从群聊机器人到团队搭子的复盘

这轮把接入会话中重复强调、后来补充、明确否定的要求合并为下面的产品约定，并逐项核对运行代码。目标是一个能融入群聊、知道什么时候开口、能把小活做完、把难活交清楚的团队搭子。增加框架数量不能代替这些行为。

## 要求与实现

| 会话中的要求                   | 当前机制与位置                                               | 验证或边界                                                    |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------- |
| 只接“做 AI 高手”群的全部消息   | 官方 SDK 网关、真实群 OpenID、签名、消息持久缓冲             | 非 @消息此前已实测；当前仍依赖本机长连接                      |
| 云端优先，不新增服务器账单     | Cloudflare Worker / D1 / 两条 Queues；本机出站执行           | 保持免费档，不自动升档；模型 API 另计                         |
| 使用 DeepSeek Flash high / max | runtime.ts 唯一模型边界，实际用量与档位记录                  | 普通聊天、查询、小活 high；重要方案、编码和夜间 max           |
| 不必记仓库全名                 | policy.ts 初始代称 + 高层语义理解 + 有依据的即时纠正与召回   | 五仓现状可查看；归属不明时追问                                |
| 不必 @Bot，能主动说话          | engagement.ts 按对象、上下文、气氛和价值判断                 | 主动说话允许观点、包袱与追问；没有固定次数和时间配额          |
| 不要每句话都回复               | 旁听判定、突发消息合并、去重与聊天游标                       | 笑声、附和、成员互聊默认安静；显式提及可触发                  |
| 有自己的身份与偏好             | voice.ts 稳定项目搭子角色 + 夜间 self_note                   | 不反复自称模型；不编造真人线下经历或他人工作                  |
| 像群友一样搞笑、抽象、有态度   | 独立嘴替、具体场景示例、自然粗口和反话理解                   | 不强制每句有梗、emoji 或粗口；真实聊天继续看反馈              |
| “想什么”和“怎么说”分开         | semantic.ts 语义/工具，voice.ts 最终表达                     | 沉默只跑参与判定；选中回复才调用嘴替                          |
| 正式工作要严肃                 | banter / work / care 模式，技术内容保护                      | 数字、链接、命令与文件名不做拟人化改写                        |
| 小概率瑕疵和碎消息             | 按事件 ID 稳定省标点、同音字、2–3 条分片                     | 只作用于短闲聊；重试不会随机多发                              |
| 重点参考 MaiBot                | 阅读实际群聊调度、表达选择、黑话学习代码                     | 独立实现适合本架构的部分，未复制 GPL 源码                     |
| 参考自然聊天 skill             | 阅读 SKILL 与风格/emoji 参考，融入实际提示                   | 没有安装整套 AstrBot；以场景评测和真实反馈验证                |
| 不懂时能问，纠正后记住         | remember_correction 原话校验、跨项目限制、即时写入           | 不把推测当确认；夜间继续复核                                  |
| 自动学习黑话与口头禅           | learning.ts 候选统计、含义与场景、来源                       | 多人多次使用或明确解释才启用；可停用且不被学习覆盖            |
| 夜深做梦、反思，不影响聊天     | Sydney 03–06、安静20分钟、新素材才 max、独立工作队列         | 每晚至多8批；来源按批处理，首次实际夜间仍待观察               |
| 记忆可追溯、可修正删除         | facts 版本、原文证据、成员修订来源、memory_blocks            | 删除的来源不能换个措辞重新学习；日记不回灌为事实              |
| 主动查新技术和热门项目         | 有项目问题的公开检索、原始链接核验、发现归档                 | 每天12/19检查；没有有用新发现就不发；不以热度代替适用性       |
| 发现 CI 失败主动处理           | 真实 check ID + commit 去重、只读初步排查、项目线索归档      | 日志不足就标明；不自动编造根因或宣称修复                      |
| 网页、仓库链接能查询           | 官方 Search / Fetch、后台检索检查点                          | 私有仓库资料由本机同步；未做全盘源码语义索引                  |
| 连续工具工作不要拖慢聊天       | 搜索/网页任务转后台，保留工具调用与结果后续跑                | 回答归到原消息；受 API 实际耗时影响                           |
| 数据、表格、PDF 能做小活       | 独立 quick / heavy utility 工作目录与 high / max 配置        | CSV/XLSX/文字PDF；扫描件 OCR 未内置                           |
| 视频和转发资料能解析           | 当前新视频链接/附件解析，公开下载、字幕、均匀抽帧            | 最多6帧；无字幕或转写时不声称听过音轨；引用旧结果不重跑       |
| 整理结果发实际文件             | 完成回执 + QQ 原生附件 + 独立交付状态                        | 生成不等于送达；未知发送结果保留人工核对，不盲目重发          |
| 复杂开发交成员的更强 AI        | 高难度交办优先方案与接力；任务可领取、回填                   | 接力包包括原始需求、仓库、基线、方案、已有结果、验收          |
| 能自己干的小开发就动手         | 独立版本分支、DSH max、相关验证、草稿 PR                     | 最多两轮；不自动合并或部署，未验证的构建转接力                |
| 多人协作不能互相覆盖           | CAS版本、失效租约、AI草稿冲突区、操作记录                    | 人工保存执行中任务会转成员接手；旧结果不能覆盖                |
| 不要反复弹原始超时命令         | 终端失败一次、进程组清理、私密诊断与人话通知                 | 群消息不包含原始 DSH 命令和本机异常                           |
| 全时在线、重启恢复             | launchd、官方重连、session恢复、持久spool、租约与完成回执    | 修复了 RESUMED 未更新在线指示的问题；不把进程存活等同可收消息 |
| 团队开发台做扎实               | 六页面、项目/搜索/负责人筛选、详细方案、资料交付、来源、统计 | 手机与桌面实际验收另见 verification.md                        |
| 独立团队仓库维护               | OmnixSI/TeamAgent、自己的锁文件/CI/文档/部署版本             | 原 InkBoard PR 关闭；旧URL和数据保留兼容                      |

## 这轮重点修掉的缺口

1. 长检索曾在聊天消费者里等待；现在保存工具检查点、转独立工具队列；普通工具不会排在max后，聊天继续。
2. CI初查缺少平台annotations，曾只能泛泛列可能阶段；现在同步真实失败注释，没有证据时不额外生成猜测。
3. 后台方案使用旧上下文时可能覆盖成员的后来修改；现在按请求版本提交，冲突另存草稿。
4. 仅有“处理完成”会掩盖附件未送达；现在独立记录生成、发送确认和未知结果，恢复只补报回执。
5. 删除记忆后，夜间可能把同一原文再抽一遍；现在留下来源删除记录，手动修订也有真实编辑来源。
6. 夜间旧批次的消息元信息曾按“最新60条”找，会漏掉旧批的转发边界；现在按准确消息 ID 批量查询。
7. 多设备登录会轮换同一个成员凭据；现在使用独立会话，可整体撤销。
8. 任务重排后会复用旧执行回执；现在执行事件、分支和回执绑定任务版本。
9. 断开后的 SDK RESUMED 没有更新在线标记；现在同时处理 READY / RESUMED，并持久化 session。
10. 分散查询可能超过免费 D1 每次50查询；夜间批量读写已合并，避免以付费升档掩盖问题。

## 下一步如何判断是否继续改

以真实失败和团队反馈为依据：漏接明确交办、无意义插话、张冠李戴、方案来源不足、文件重复发送、人工内容被覆盖，都应有具体场景与回归检查。每次改变人格提示，用聊天、工作、未知梗和不应插话的场景复核。不能用“更抽象、更会爆粗”的词数当质量指标，也不能把测试通过当成24小时稳定运行。

目前有价值但尚未完成的工作是：官方云端 QQ 回调、首次真实夜间记录、24小时故障观察、更多业务仓库构建环境，以及带版本引用的更深源码检索。OCR、音频转写和更多付费工具要按实际需求再接，先把已有链路验收清楚。
